# 이슈/토론 v0.7.2 — 사건 타임라인 · 이슈 미디어 · 접속자 수

> **작성일**: 2026-07-23
> **범위**: 이슈에 **맥락**과 **생동감**을 붙인다. 사건(Event) 타임라인, 이슈 단위 미디어 클러스터, 실시간 접속자 수(presence), 채팅방의 이슈 컨텍스트 로드.
> **성격**: **분리 보류 문서.** v0.7.1 초판에 포함돼 있었으나 백엔드 배포 단위(v1.3.5~v1.3.8)에 맞춰 떼어냈다. **착수 시점 미정** — 백엔드 일정 회신 대기.
> **선행 문서**: `docs/prd/v0.7.1_issue-restructure.md`

## 0. 왜 분리했는가

v0.7.1 초판은 위키·스레드·사건·미디어·presence 를 한 배포에 담았다. 백엔드가 이를 5개 배포로 나눠 잡았고, 웹이 하나로 묶여 있으면 **백엔드 4개 배포를 전부 기다린 뒤에야 아무것도 못 내보내는 상태**가 된다.

| 항목 | 대응 백엔드 배포 | 백엔드 상태 |
|---|---|---|
| 사건(Event) 타임라인 | v1.3.5 | 미착수. 주제/위키와 의존 없음 |
| 채팅방 상세 확장 (이슈+주제목록+미디어) | v1.3.6 | 미착수. **프론트 계약 변경**이라 웹/앱 동기화 필요 |
| 이슈 미디어 클러스터 | v1.3.7 | 미착수. **선행 조사 필요** (§3.3) |
| 접속자 수 (presence) | v1.3.8 | 미착수. 카운터 leak 설계 필요 |

**웹은 이 순서를 강제하지 않는다.** 백엔드가 내보내는 순서대로 웹도 조각내서 낸다. 넷을 한 배포로 묶지 않는다.

## 1. 사건 (Event) — 이슈의 타임라인

### 1.1 정의

이슈 안에서 일어난 사실 단위. **읽기 전용**(유저가 만들지 않음, 운영/서버가 생성).

**사건이 소유하는 것은 미디어 클러스터뿐이다.** 채팅방이나 위키를 갖지 않는다 — 계층이 한 단 더 깊어지지 않는다. (백엔드에 전달 완료, 백엔드 권장안과 일치)

```
이슈: 윤석열 계엄
├ 사건 1  12/03  비상계엄 선포        [뉴스 12 · 유튜브 4]
├ 사건 2  12/04  국회 해제 의결       [뉴스 31 · 커뮤 8]
└ 사건 3  12/14  탄핵소추안 가결      [뉴스 55]
```

### 1.2 화면

이슈 상세(`/issue/[id]/[slug]`)에 **[사건] 탭**을 추가한다. `occurred_at` 내림차순 타임라인.

- 사건 카드 = 제목 · 발생 시각 · 요약 · 미디어 카운트 배지
- 사건 탭 → 해당 사건의 미디어만 필터링해 미디어 탭으로 이동

### 1.3 컴포넌트

| 경로 | 역할 |
|---|---|
| `src/components/issue/EventTimeline.tsx` | 사건 타임라인 |
| `src/lib/api/event.ts` | 사건 조회 (커서 페이징) |

> 사건이 이슈당 3건일지 300건일지가 **생성 주체(운영 수동 vs 자동 클러스터링)에 따라 달라진다.** 어느 쪽이든 **커서 페이징 전제로 받아둔다** — 나중에 자동화로 바뀌어도 프론트를 고치지 않아도 되게.

## 2. 이슈 미디어 클러스터

### 2.1 목표

이슈에 클러스터링된 뉴스/유튜브/커뮤니티를 이슈 상세 **[미디어] 탭**에 노출한다. 사건 단위 필터도 지원.

현재 미디어는 **홈 전용**(`GET /api/v1/home/media?type=&time=`)이고 이슈 필터가 없다.

### 2.2 요청 방향

기존 `MediaResponse` 스키마를 **재사용**하고 `issueId`/`eventId` 필터만 추가하는 형태를 우선 요청한다. 신규 스키마를 만들지 않는 편이 프론트 재사용에 유리하다 (`src/lib/api/home.ts` 의 미디어 렌더를 그대로 쓸 수 있다).

### 2.3 ⚠️ 선행 조건 — 미디어 수집이 멈춰 있다

백엔드 실측(2026-07-22):

| type | 최종 수집 |
|---|---|
| news | **2026-06-30** (3주 전) |
| COMMUNITY | **2026-06-30** (3주 전) |
| youtube | **2025-07-27** (약 1년 전) |

`youtube` 는 알려진 API 할당량 소진 이슈지만, **news/community 가 6/30 에 동시에 끊긴 것은 별개 원인**일 가능성이 높다.

> **미디어 탭을 지금 만들어도 보여줄 데이터가 없다.** 수집 재개가 이 항목의 선행 조건이며, 백엔드 조사 결과에 따라 v0.7.2 안에서도 가장 뒤로 밀릴 수 있다.

또한 클러스터링 파이프라인(`toronchul_data_v1`, Python)은 **이미 구현돼 있으나 하루치 시범 실행 후 멈춘 상태**다(2026-03-03 하루치 21건, `media` 19,729건 중 59건만 연결). 이슈명도 `클러스터_001` 형식이라 사용자 노출 전 네이밍이 필요하다. → 자동 클러스터링을 이 배포에 넣을지는 백엔드 결정 사항.

### 2.4 컴포넌트

| 경로 | 역할 |
|---|---|
| `src/components/issue/IssueMediaTab.tsx` | 미디어 클러스터 (뉴스/유튜브/커뮤니티 필터) |
| `src/lib/api/media.ts` | 이슈 미디어 — `home.ts` 에서 분리 |

## 3. 접속자 수 (presence)

### 3.1 노출 위치

| 위치 | 표시 | 범위 |
|---|---|---|
| 홈 / 이슈 상세 헤더 | `🌐 전체 접속 1,204명` | 웹 + 모바일 앱 합산 |
| 이슈 상세 CTA / 채팅방 헤더 | `👥 38명 접속 중` | 해당 채팅방 |

### 3.2 집계 단위 — **유저 단위** (초판에서 변경)

초판은 **세션 단위**(웹+앱 동시 접속 시 2로 셈)를 제안했으나, **유저 단위(userId distinct)로 정정한다.**

- "총 접속 **사용자**"라는 표시 문구와 의미가 일치한다
- 세션 단위의 유일한 장점이던 "비로그인 방문자 카운트"는 **익명 연결의 sessionId fallback** 으로 해결된다
- 백엔드 v1.3.8 설계와도 일치

### 3.3 전달 방식

폴링 대신 기존 STOMP 연결에 presence 를 얹는다.

- 방별: `/topic/room{N}/presence` — 5~10초 debounce 브로드캐스트
- 전역: 전역 토픽 또는 `GET /api/v1/presence` 폴링
- 폴백: 소켓 미연결 시 `GET /api/v1/presence` 1회 조회 후 30s 폴링
- 기존 CONNECT 인증(`Authorization: Bearer`, 대문자 — v0.7 §3 실측 확정) 규칙 그대로

> **백엔드 주의사항**: 비정상 종료로 DISCONNECT 이벤트가 유실되면 카운터가 샌다(leak). TTL / 주기적 reconcile / 하트비트 만료 설계가 필요하다. **웹은 카운트가 실제보다 높게 나올 수 있다는 전제로 UI 를 만든다** — 정확한 수치가 아니라 "활발함"의 신호로 표현한다.

### 3.4 컴포넌트

| 경로 | 역할 |
|---|---|
| `src/components/TDS/DePresenceBadge.tsx` | 접속자 수 배지 (props: `count`, `scope`) — leaf, 데이터는 props (불문율 #5) |
| `src/store/usePresenceStore.ts` | **persist 없음** — 휘발성 실시간 값이므로 `_hasHydrated` 불필요 |
| `src/lib/api/chatSocket.ts` | (수정) presence 토픽 구독 추가 |
| `src/lib/api/presence.ts` | 폴백 조회 |

```
usePresenceStore
 ├ globalCount: number
 ├ roomCounts: Record<number, number>
 └ STOMP 구독/해제 관리
```

## 4. 채팅방 이슈 컨텍스트 (백엔드 v1.3.6)

채팅방을 "메시지만 흐르는 화면"에서 벗어나게 한다. 상단에 **이슈 헤더**를 고정한다.

```
┌ 이슈 헤더 (축약)  윤석열 계엄        👥 38명 접속 중
├ 진행 중인 토론 ──────────── (v0.7.1 에서 이미 구현)
│  [진행 중] 계엄은 위헌인가   62:38  →
├ ─────────────────────────────────
│  (메시지 목록)
└ [입력창]
```

- 백엔드가 `GET /api/v1/room` 응답에 `issue` / `media` / `presence` 를 **추가**한다(필드 추가는 안전, 호환성 약속 §2.3).
- 이 항목의 실질은 백엔드가 현재 반환하는 **전역 속보 10건**(`findTop10BreakingNews()`)을 **해당 이슈의 클러스터 미디어로 교체**하는 것이다. → §2 에 의존한다.
