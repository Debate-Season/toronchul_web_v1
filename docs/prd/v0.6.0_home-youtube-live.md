# 홈 실시간 Live v0.6 — 유튜브 라이브 노출

> **작업일**: 2026-07-18
> **범위**: 홈 화면 "실시간 Live" 섹션을 **유튜브 라이브** 노출로 정립. 데이터 배선 수정, 유튜브 카드 신설, 2-per-view width-fill 캐러셀. + PiP 버튼 도입 가능성 조사.
> **결론 요약**: 실시간 Live = 유튜브 라이브(2개씩 width-fill, 좌우 스크롤). **PiP 버튼은 유튜브 정책·기술 제약으로 미구현 권고**(§5).

## 1. 배경 — "실시간 Live"가 렌더되지 않던 문제

- 홈은 `GET /api/v1/users/home` 만 호출했는데, 이 API의 `data`는 **이슈 목록 배열(IssueBriefResponse)** 뿐이다. `bestChatRooms`·`chatRooms`는 응답에 없다.
- `fetchHome`이 배열 응답을 `{ issueRooms, chatRooms: [], bestChatRooms: [] }`로 파싱 → **`bestChatRooms`가 항상 빈 배열** → 섹션 렌더 조건(`length > 0`)에 걸려 "실시간 Live"가 **통째로 안 보였다**.
- 원래 이 섹션은 인기 토론방(`LiveDebateCard`)을 LIVE 배지로 보여주는 구조였으나, **의도는 유튜브 라이브 노출**로 재정의.

## 2. 데이터 소스 (백엔드 실측 확인, 2026-07-18)

| 데이터 | 엔드포인트 | 필드 |
|---|---|---|
| 유튜브 라이브 | `GET /api/v1/home/media` → `youtubeLiveContainer` | `id`, `title`, `supplier`(채널), `videoId`, `category`, `createAt`, `src`(썸네일) |

- `youtubeLiveContainer`는 **객체(map)** 형태 → `fetchMedia`가 `Object.values()`로 배열화하여 `MediaResponse.youtubeLive`로 반환(기존 로직 재사용, 이미 로드 중이었음).
- 익명 호출 응답 5건 확인. 샘플 `videoId`="YFerag85l-M".
- **시청 링크**: `https://www.youtube.com/watch?v=${videoId}` (HTTP 200 확인).
- **썸네일**: `https://i.ytimg.com/vi/${videoId}/hqdefault.jpg` (HTTP 200 확인). 백엔드 `src`는 저해상 `default_live.jpg`라 카드 품질 위해 `hqdefault` 사용.
- `title`에 HTML 엔티티(`&#39;` 등)가 섞여 옴 → 카드에서 결정적(SSR-safe) 치환으로 디코드.

## 4. 캐러셀 (2-per-view width-fill)

`HorizontalCarousel({ perView })` — `perView` 지정 시:
- 각 아이템을 균등 폭 슬롯으로 래핑: `flex: 0 0 calc((100% - (perView-1)*12px) / perView)` (gap-3=12px). → **한 화면 2개, width-fill**.
- **버튼 인셋**: 좌우 화살표를 `left-2`/`right-2`로 옮겨 스크롤 섹션 안쪽으로 오버레이.
- **2개씩 이동**: 클릭 시 `(슬롯폭 + gap) × perView` 만큼 `scrollBy`. 계산상 다음 페이지 첫 아이템이 왼쪽 정렬(= `clientWidth + gap`).
- **홀수 마지막 항목**: 슬롯 폭이 고정이라 마지막 하나만 남으면 2열과 동일한 반 칸 폭 + 나머지 공백으로 렌더(추가 처리 불필요).
- `perView` 미지정 시 기존 동작(아이템 고유 폭, `clientWidth*0.7` 스크롤) 유지 → 재사용 안전.

## 5. PiP / 재생 방식 — 공식 임베드 채택 (커스텀 PiP 버튼 불가)

**커스텀 "우측 상단 PiP 버튼"은 도입하지 않음** — 공식 정책 조항으로 확인:
- **오버레이 금지** (Required Minimum Functionality, "Overlays and frames"): *"You must not display overlays, frames, or other visual elements in front of any part of a YouTube embedded player, including player controls."* → 플레이어 위 커스텀 버튼 불가.
- **백그라운드 플레이어 금지** (Developer Policies III.I.9): *"...play content... from a background player, meaning a player that is not displayed in the page, tab, or screen that the user is viewing."* → PiP류 화면 밖 지속 재생 기능 제작·홍보 금지.
- **플레이어 기능 개변 금지** (III.I.6): *"Modify, build upon, or block any portion or functionality of a YouTube player."* + IFrame API에 **PiP 트리거 메서드 없음** + 교차출처 iframe에 `requestPictureInPicture()` 호출 불가.

**채택한 공식 방식**: 카드 썸네일(파사드) 클릭 → **우하단 논모달 플로팅 미니 플레이어**(faux-PiP)로 공식 IFrame 재생. 모달이 아니라 페이지 위에 떠 있어 **나머지 페이지를 조작·이동하면서 계속 시청**할 수 있다(브라우저 PiP처럼).
- 왜 플로팅+지속이 정책상 OK: 백그라운드 플레이어 금지(III.I.9)는 "사용자가 보는 화면에 **표시되지 않는** 플레이어"를 막는 것 → 우하단에 **계속 보이게 떠 있는** 플레이어는, 페이지를 이동해도 화면에 표시되므로 저촉 안 됨. (반대로 숨기거나 오디오-only로 만들면 그 순간 위반)
- 지킨 조건: ① 항상 화면에 보이게(숨김/오디오-only 금지) ② 최소 크기 충족(데스크톱 400×225, 모바일 풀폭≥200) ③ 플레이어 위 오버레이 없음(닫기 X는 상단 바=플레이어 밖, 제목/채널은 영상 아래) ④ 브랜딩·컨트롤 유지 ⑤ 닫기 시 정지.
- `iframe allow="...; picture-in-picture; ..."` + `allowFullScreen` → 사용자가 브라우저 기본 PiP·전체화면 사용 가능(우리가 PiP 버튼 만들거나 트리거하지 않음).
- 구현:
  - `src/store/useYoutubePlayerStore.ts` — 현재 재생 영상 공유 스토어(persist 아님, 단일 플로팅 인스턴스). 카드가 여러 개라도 하나만 재생.
  - `src/components/home/YoutubeFloatingPlayer.tsx` — 우하단 고정 패널(상단 X → 공식 iframe → 영상 아래 제목/채널). **루트 레이아웃(`RedditLayout`)에 마운트** → 소프트 내비게이션(이슈맵·이슈·토론 등) 동안 iframe DOM이 보존되어 **재생 유지**.
  - `src/components/home/YoutubeLiveCard.tsx` — 파사드 클릭 시 `openPlayer()` 호출.
