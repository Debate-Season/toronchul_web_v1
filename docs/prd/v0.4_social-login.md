## 2. 근본 원인 (진단 결과)

코드는 v0.2 에서 이미 완성돼 있었고, 실패는 전부 **환경변수/콘솔 설정** 문제였음.

| # | 원인 | 심각도 | 위치 |
|---|---|---|---|
| C-1 | **Vercel 카카오 `client_id` 가 네이티브 앱 키** (`18af8def...`) — OAuth 는 REST API 키(`eb083b8a...`)여야 함 | 🔴 치명 | Vercel env |
| C-2 | **Vercel 카카오 redirect URI 가 localhost** (`http://localhost:3000/oauth/callback/kakao`) — 프로덕션 URL 이어야 함 | 🔴 치명 | Vercel env |
| C-3 | **Vercel 에 애플 env 부재** — `NEXT_PUBLIC_APPLE_CLIENT_ID`, `NEXT_PUBLIC_APPLE_REDIRECT_URI` 둘 다 없음 → `client_id` 빈 값으로 authorize URL 생성 | 🔴 치명 | Vercel env |
| C-4 | **애플 redirect URI 경로 오류** — `.env.local` 에 `/oauth/callback/apple`(클라 페이지)로 설정. 애플은 `response_mode=form_post` 라 POST 를 보내는데 클라 페이지는 405. POST 수신은 `/api/auth/apple/callback`(Route Handler) | 🟠 코드/설정 | `.env.local`, `.env.example` |

### 핵심 함정 두 가지

1. **카카오 키 종류** (v0.2 ADR-04 교훈의 연장): 같은 카카오 앱이라도 **네이티브 앱 키 ≠ REST API 키**. OAuth `/oauth/authorize` + `/oauth/token` 의 `client_id` 는 반드시 **REST API 키**. Vercel 에 네이티브 키가 들어가 있어 근본적으로 실패.
2. **애플 form_post 수신 경로**: `redirect_uri` 는 애플이 **POST** 로 호출하므로 Route Handler(`/api/auth/apple/callback`)여야 함. 이 핸들러가 303 으로 클라 페이지 `/oauth/callback/apple?id_token=...` 로 리다이렉트. (v0.2 ADR-05 참조)

## 5. 애플 설정 방법 (전체 가이드)

> 상세 원본: `docs/apple-login-plan.md`. 아래는 도메인 전환 기준 요약.

### 5.1 Apple Developer 접속
1. [developer.apple.com](https://developer.apple.com) → **Account** 로그인
2. **Certificates, Identifiers & Profiles** 진입

### 5.2 App ID 확인
1. **Identifiers** → 필터 **App IDs**
2. 토론철 App ID (`com.rosyocean.debateseason`) 선택
3. **Capabilities** 에서 **Sign In with Apple** 체크 확인 (없으면 체크 → Save)

### 5.3 Services ID 생성/설정 (웹 로그인 핵심)
1. **Identifiers** → 필터 **Services IDs** → **+**
2. **Description**: `토론철 웹 로그인`, **Identifier**: `com.rosyocean.debateseason.web` → Register
3. 목록에서 방금 항목 클릭 → **Sign In with Apple** 체크 → **Configure**
4. Configure:
   - **Primary App ID**: `com.rosyocean.debateseason`
   - **Domains and Subdomains**:
     ```
     toronchul.app
     ```
   - **Return URLs**  ← 반드시 `/api/auth/apple/callback` (page 아님):
     ```
     https://toronchul.app/api/auth/apple/callback
     http://localhost:3000/api/auth/apple/callback
     ```
   - **Save** → Continue → Save

> ⚠️ **Domains 에 `localhost` 는 등록 불가/불안정**. 로컬 애플 로그인 테스트가 필요하면 [ngrok](https://ngrok.com) 등으로 HTTPS 터널을 열어 그 도메인을 등록하거나, 애플 로그인은 배포 환경에서 검증하는 것을 권장. Return URL 의 localhost 는 등록되면 두고, 안 되면 프로덕션만으로 진행.

### 5.4 Key(.p8) 생성 — 백엔드 id_token 검증용
1. **Keys** → **+**
2. **Key Name**: `토론철 Sign In with Apple` → **Sign In with Apple** 체크 → **Configure** → Primary App ID 선택 → Save
3. Continue → Register → **Download** (`.p8`, **1회만 다운로드 가능**, 안전 보관)
4. 화면의 **Key ID** 메모 (예: `ABC123DEF4`)

### 5.5 Team ID 확인
- Account → **Membership details** → **Team ID** 메모

### 5.6 백엔드에 전달할 정보
| 항목 | 값 |
|---|---|
| Services ID (client_id) | `com.rosyocean.debateseason.web` |
| Key ID | 5.4 메모값 |
| Team ID | 5.5 메모값 |
| `.p8` Key 파일 | 5.4 다운로드 파일 |

**백엔드 확인 사항**:
- [ ] `/api/v2/users/login` 이 `socialType: "apple"` + `idToken` 처리
- [ ] 애플 공개키로 id_token(JWT) 검증 로직
- [ ] **웹 Services ID(`...web`) 를 audience 로 허용** — 앱(`com.rosyocean.debateseason`)과 다르므로 둘 다 허용 필요 (v0.2 ADR-04 카카오와 동일한 함정)

## 6. 애플 로그인 플로우 (재확인)

```
[Apple 버튼]  (src/lib/auth/apple.ts redirectToApple)
  → https://appleid.apple.com/auth/authorize
      ?client_id=com.rosyocean.debateseason.web
      &redirect_uri=https://toronchul.app/api/auth/apple/callback
      &response_type=code id_token&response_mode=form_post&scope=name email&state=...
  → Apple 인증
  → POST https://toronchul.app/api/auth/apple/callback   (form_post)
      ↳ src/app/api/auth/apple/callback/route.ts 가 수신
  → 303 GET /oauth/callback/apple?id_token=...&state=...
      ↳ src/app/oauth/callback/apple/page.tsx (state 검증)
  → POST /api/v2/users/login { socialType: "apple", idToken }  (apiFetch)
      ↳ { accessToken, refreshToken, profileStatus, termsStatus }
  → Zustand setTokens → router.push("/")
```
