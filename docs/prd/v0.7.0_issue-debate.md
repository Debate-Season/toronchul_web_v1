## 2. API 계약 (실측 확인)

| Method | Path | 파라미터 | 응답/비고 |
|---|---|---|---|
| GET | `/api/v1/issue` | `issue-id`(필수), `page` | `IssueDetailResponse` |
| GET | `/api/v1/room` | `chatroom-id`(필수) | `ChatRoomResponse`(=RoomDetailResponse) |
| POST | `/api/v1/room/vote` | `opinion=AGREE\|DISAGREE`, `chatroom-id` (쿼리, **body 없음**) | `ApiResultString`. 로그인 필요 |
| GET | `/api/v1/chat/rooms/{roomId}/messages` | `cursor` | `ChatMessagesResponse` — **인증 필요(401)** |

- `IssueDetailResponse`: `title, bookMarkState, bookMarks, chats, map(Record<string,number>), chatRoomMap(방 목록)`.
  - **`map` = 참여 커뮤니티**: 키=커뮤니티 **아이콘 상대경로**(예 `"community/icons/bobaedream.png"`), 값=참여 수. (실측 `{"community/icons/bobaedream.png":1}`)
  - `chats` 는 실측 0으로 오는 경우가 있어 "토론방 수"로 부적합 → **`chatRoomMap.length`** 사용.
- `RoomDetailResponse.opinion` = **로그인 유저의 투표 상태**: `AGREE`/`DISAGREE`=투표 완료, `NEUTRAL`(또는 빈값)=미투표. (비로그인은 `NEUTRAL`)

## 3. 토론방 찬반 투표 · 입장 (신규)

**공유 컴포넌트** `src/components/room/RoomDetail.tsx` — 기존 중복 라우트 2개를 통합해 사용:
- `/room/[id]`(raw id, 홈 찬반토론 진입), `/issue/[id]/[slug]/[roomId]/[roomSlug]`(base36, 이슈 진입) → 둘 다 `<RoomDetail roomId backHref backLabel/>`.

**플로우**
1. 찬반 비율 바 + 찬성/반대 **투표 버튼**(현재 내 투표 하이라이트).
2. **투표(POST /room/vote)** → 재조회로 `opinion`·찬반수 갱신.
3. **입장하기 버튼**: `opinion∈{AGREE,DISAGREE}`(투표 완료)일 때만 **활성**, 그 전엔 disabled.
4. **로그인 게이팅**: 비로그인 유저가 투표/입장 시도 → **로그인 모달**. (`opinion`이 NEUTRAL이라 입장도 자동 disabled)
5. 입장하기 → `/room/{roomId}/chat`.
6. **팀 점수(teams) 섹션 숨김**.

**로그인 모달 재사용화**: `RedditLayout` 내부에 갇혀 있던 `LoginModal`을 `src/components/auth/LoginModal.tsx`로 추출 → 헤더·투표·입장 등 어디서든 재사용.

**채팅 화면** `/room/[id]/chat` (`src/components/room/ChatRoom.tsx`, `src/lib/api/chat.ts`):
- **메시지 조회**: `GET /chat/rooms/{roomId}/messages`(커서). "이전 대화 더 보기"로 과거 메시지 페이지네이션.
- **메시지 렌더**: 아바타(`profileColor`), 커뮤니티(`userCommunity`), 닉네임, 의견(`opinionType` 찬성/반대), 본문, 시간. `messageType` JOIN/LEAVE=시스템 라인, CHAT=말풍선.
- **반응**: 이번 범위 아님 — **숨김**(API 함수 `reactToMessage`는 남겨둠).
- **비로그인 게이팅**: 메시지 API가 인증 필수 → 비로그인 시 로그인 유도 + 모달.
- **메시지 전송 = STOMP over WebSocket** (REST 전송 엔드포인트 없음) — `src/lib/api/chatSocket.ts` 구현 완료.
  - 연결: **`wss://api.toronchul.app/prod/ws-stomp`** (env `NEXT_PUBLIC_WS_URL`). **raw WebSocket** — SockJS 폴백 불필요(101 업그레이드 실측).
  - 구독(수신): `/topic/room{roomId}` · 발행(전송): `/stomp/chat.room.{roomId}` (출처 `docs/claude-md-reference.md:106`).
  - **인증 = STOMP CONNECT 단계, 헤더명 `Authorization: Bearer {token}`** (실측 확정).
    - ⚠️ **대소문자 구분**: 소문자 `authorization`·`token`·`accessToken`·`?token=` 쿼리는 서버가 읽지 않음("인증 토큰이 필요합니다"로 거절). `connectHeaders` 는 verbatim 전달되므로 반드시 `Authorization` 표기.
    - 토큰 무효 시 ERROR `유효하지 않은 인증 토큰입니다.` + close 1002 → `unauthorized` 상태로 재연결 루프 중단.
  - 라이브러리: **`@stomp/stompjs` ^7.3.0** 추가.
  - ❗ **발행 payload 형식은 미검증** — REST Swagger 에 STOMP `@MessageMapping` DTO 가 없고, 유효 토큰 없이는 CONNECT 가 막혀 실측 불가. 현재 `chatSocket.ts` 의 `buildPayload()` 가 `{roomId, messageType:"CHAT", content}` (ChatMessageResponse 역산 **추정**)로 보냄. 로그인 세션 검증 후 **이 함수 하나만** 고치면 됨.
  - 입력창 활성화 + 연결 상태 표시(연결 중/끊김/세션 만료), 500자 제한, 브로커 echo id 중복 제거.
- ⚠️ 메시지 필드 값 형식(userCommunity 경로/이름, profileColor engName, timeStamp 포맷, items 정렬)은 인증 응답으로만 검증 가능 → **방어적 렌더**(경로 감지·색상 fallback·시간 파싱)로 구현했고, 로그인 세션에서 실제 응답 확인 후 미세 조정 필요.

## 4. 이슈 상세 수정 (`src/app/issue/[id]/[slug]/page.tsx`)

- **스크랩 아이콘 제거** — 스크랩 기능 미구현이므로 헤더의 `Bookmark`+`bookMarks` 표시 삭제.
- **토론방 수 정정** — 헤더를 `data.chats`(0으로 오던 값) → **`토론방 {chatRoomMap.length}개`**.
- **커뮤니티 반응 → 참여 커뮤니티** — 섹션명 변경 + `map` 키(아이콘 경로)를 텍스트("파일명처럼")가 아니라 **`imageUrl(key)` 아이콘 이미지**로 렌더.
