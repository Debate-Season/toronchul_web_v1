## 0. 왜 분리했고 왜 v1.1.0 인가

v0.7.1 초판은 위키·스레드·사건·미디어·presence 를 한 배포에 담았다. 백엔드가 이를 5개 배포로 나눠 잡았고, 웹이 하나로 묶여 있으면 **백엔드 4개 배포를 전부 기다린 뒤에야 아무것도 못 내보내는 상태**가 된다.

**2026-08-17 개정**: 이 문서는 원래 `v0.7.2` 였다. 담긴 항목이 전부 "있으면 좋지만 없어도 서비스가 성립하는" 것들이고, 실제로 **정식 출시 이후로 미루기로 결정**됐으므로 **정식 출시(v1.0.0) 다음 마이너인 v1.1.0** 으로 번호를 바꿨다. 같은 이유로 **토론위키가 v0.7.1 에서 이 문서로 넘어왔다**(§1).

| 항목 | 대응 백엔드 배포 | 백엔드 상태 |
|---|---|---|
| **토론위키** | **v1.3.4 (배포 완료)** | **API 는 이미 있다. 게시된 문서가 0건이라 웹이 미룬 것** (§1.4) |
| 사건(Event) 타임라인 | v1.3.5 | 미착수. 주제/위키와 의존 없음 |
| 채팅방 상세 확장 (이슈+주제목록+미디어) | v1.3.6 | 미착수. **프론트 계약 변경**이라 웹/앱 동기화 필요 |
| 이슈 미디어 클러스터 | v1.3.7 | 미착수. **선행 조사 필요** (§3.3) |
| 접속자 수 (presence) | v1.3.8 | 미착수. 카운터 leak 설계 필요 |

**웹은 이 순서를 강제하지 않는다.** 백엔드가 내보내는 순서대로 웹도 조각내서 낸다. 다섯을 한 배포로 묶지 않는다.

## 1. 토론위키 (DebateWiki) — v0.7.1 에서 이관

### 1.1 성격 — **토론철 AI 가 쓰는 이슈 브리핑**

**이슈와 1:1.** 토론철 AI 가 이슈의 원천 재료로 초안을 쓰고 ADMIN 이 게시한다. **유저 편집 없음.** 웹은 **읽기 전용 렌더**만 담당한다.

```
이슈 (Issue)
├── 토론위키 (DebateWiki)   ← ★ 이슈당 1장. AI 작성 + ADMIN 게시.
└── 컨테이너 채팅방          ← v0.7.1 에서 구현 완료
```

> 초판은 `주제 1:1 위키` + `집단 편집` 설계였다. 2026-07-29 실측에서 **이슈 1:1 · ADMIN 전용 쓰기**로 확정됐다. 집단 편집 위키가 아니라 **AI 가 정리하는 이슈 브리핑 문서**이므로 되돌리기·편집 잠금·훼손 대응은 불필요하다.

### 1.2 배포된 API (2026-07-29 실측)

| 엔드포인트 | 내용 | 웹 |
|---|---|---|
| `GET /api/v2/wiki?issue-id=` | **이슈당 위키 1장**(게시본). 미게시면 전 필드 null, 에러 아님 | ✅ 웹이 쓸 유일한 엔드포인트 |
| `POST /api/v1/admin/wiki/generate?issue-id=` | **AI 초안 생성** — LLM 이 DRAFT 리비전 저장(게시 안 함). 생성기 미구성 시 503 `WIKI_GENERATION_UNAVAILABLE` | ❌ 호출 안 함 |
| `POST /api/v1/admin/wiki/revisions` | ADMIN 수동 리비전 추가 `{issueId, content(Markdown), editSummary}` | ❌ 호출 안 함 |
| `POST /api/v1/admin/wiki/publish` | `{revisionId}` → PUBLISHED 전환. 옛 리비전 id 로 재게시 = **롤백** | ❌ 호출 안 함 |

ADMIN 쓰기 3종은 **웹에서 호출하지 않는다** — 어드민 UI 를 만들지 않기로 확정됐다(v0.7.1 §2.2-6).

### 1.3 상태 전이 — 웹이 구분할 것은 2개뿐

```
[이슈 생성]
     │  ADMIN: POST /admin/wiki/generate  (AI 초안 → DRAFT 리비전)
     ▼
 DebateWiki(미게시)  ── status/content = null, 웹은 "준비 중" 안내
     │  ADMIN: POST /admin/wiki/publish {revisionId}
     ▼
 DebateWiki(PUBLISHED)  ── content(Markdown) 렌더
     │  옛 revisionId 로 재게시 = 롤백
     ▼
 (반복)
```

- 웹이 구분할 상태는 **미게시 / 게시됨** 둘뿐이다. `ACTIVE/ARCHIVED/HIDDEN` 3상태 설계는 폐기.
- 웹이 처리할 빈 상태도 **"AI 초안이 아직 게시되지 않음"** 하나다. "첫 문단을 작성해보세요" CTA·작성 템플릿은 만들지 않는다.

### 1.4 ⚠️ 왜 지금이 아닌가 — 게시된 문서가 0건

2026-07-29 실측: **11개 이슈 전부** `status/content/revisionId/updatedAt` 이 null. AI 초안이 한 건도 생성·게시되지 않았다.

> **지금 붙이면 모든 이슈에서 "준비 중" 안내만 렌더된다.** 이 항목의 선행 조건은 백엔드 API 가 아니라 **콘텐츠 파이프라인 가동**(초안 생성 → ADMIN 게시)이다. §3.3 의 미디어 수집 중단과 같은 성격의 블로커다.

### 1.5 설계 결정 3건 — 전부 확정됨 (2026-07-29)

| # | 항목 | 확정 | 근거 |
|---|---|---|---|
| 1 | 위키 편집 단위 | **문서 전체 리비전** (문단 단위 아님) | `revisions` 바디가 `{issueId, content, editSummary}` |
| 2 | AI 초안 유무 | **있다** (잠정 전제와 반대) | `admin/wiki/generate` 배포됨, 응답에 `model` 필드 |
| 3 | 편집 권한 | **토론철 AI + ADMIN 전용** | 쓰기 3종이 전부 `/api/v1/admin/wiki/*` 하위 |

→ 웹은 편집을 하지 않으므로 **`content` 를 Markdown 으로 렌더하기만 하면 된다.** `WikiBlockEditor`, `WikiRevisionList`, 편집 버튼은 전부 범위 제외.

### 1.6 화면 · 컴포넌트

| 경로 | 역할 | 상태 |
|---|---|---|
| `src/lib/api/wiki.ts` | `GET /api/v2/wiki` 조회 | 미작성 |
| `src/components/wiki/IssueWiki.tsx` | Markdown 렌더 + 미게시 빈 상태 | 미작성 |
| ~~`src/components/wiki/WikiRevisionList.tsx`~~ | 편집 이력 | **제외** — 편집 없음 |
| ~~`src/components/wiki/WikiBlockEditor.tsx`~~ | 문단 편집 | **제외** — 문서 전체 리비전 |
| ~~`src/components/issue/ArchivedWikiList.tsx`~~ | 지난 토론 목록 | **제외** — 위키가 이슈당 1장 |

라우트는 **이슈 상세의 탭**으로 붙인다. `/issue/[id]/[slug]/wiki` 같은 하위 라우트는 만들지 않는다 — 위키가 이슈당 1장이라 목록 라우트가 성립하지 않는다(v0.7.1 §5.1).

### 1.7 남은 논점 — 주제별 아카이브 상실

위키가 이슈 1장이 되면서 **"쟁점별 지난 토론" 산출물이 없어졌다.** v0.7.1 §1 이 잡았던 "아카이브 부재" 문제가 이슈 단위로만 해소된다.

- (a) 이슈 위키 1장으로 충분하다 — 현행 유지
- (b) 쟁점별 정리가 필요하다 — 백엔드에 **스레드 단위 위키** 재요청

→ 착수 시점에 결정한다. AI 초안 품질을 보고 판단하는 편이 낫다.

## 2. 사건 (Event) — 이슈의 타임라인

### 2.1 정의

이슈 안에서 일어난 사실 단위. **읽기 전용**(유저가 만들지 않음, 운영/서버가 생성).

**사건이 소유하는 것은 미디어 클러스터뿐이다.** 채팅방이나 위키를 갖지 않는다 — 계층이 한 단 더 깊어지지 않는다. (백엔드에 전달 완료, 백엔드 권장안과 일치)

```
이슈: 윤석열 계엄
├ 사건 1  12/03  비상계엄 선포        [뉴스 12 · 유튜브 4]
├ 사건 2  12/04  국회 해제 의결       [뉴스 31 · 커뮤 8]
└ 사건 3  12/14  탄핵소추안 가결      [뉴스 55]
```

### 2.2 화면

이슈 상세(`/issue/[id]/[slug]`)에 **[사건] 탭**을 추가한다. `occurred_at` 내림차순 타임라인.

- 사건 카드 = 제목 · 발생 시각 · 요약 · 미디어 카운트 배지
- 사건 탭 → 해당 사건의 미디어만 필터링해 미디어 탭으로 이동

### 2.3 컴포넌트

| 경로 | 역할 |
|---|---|
| `src/components/issue/EventTimeline.tsx` | 사건 타임라인 |
| `src/lib/api/event.ts` | 사건 조회 (커서 페이징) |

> 사건이 이슈당 3건일지 300건일지가 **생성 주체(운영 수동 vs 자동 클러스터링)에 따라 달라진다.** 어느 쪽이든 **커서 페이징 전제로 받아둔다** — 나중에 자동화로 바뀌어도 프론트를 고치지 않아도 되게.

## 3. 이슈 미디어 클러스터

### 3.1 목표

이슈에 클러스터링된 뉴스/유튜브/커뮤니티를 이슈 상세 **[미디어] 탭**에 노출한다. 사건 단위 필터도 지원.

현재 미디어는 **홈 전용**(`GET /api/v1/home/media?type=&time=`)이고 이슈 필터가 없다.

### 3.2 요청 방향

기존 `MediaResponse` 스키마를 **재사용**하고 `issueId`/`eventId` 필터만 추가하는 형태를 우선 요청한다. 신규 스키마를 만들지 않는 편이 프론트 재사용에 유리하다 (`src/lib/api/home.ts` 의 미디어 렌더를 그대로 쓸 수 있다).

### 3.3 ⚠️ 선행 조건 — 미디어 수집이 멈춰 있다

백엔드 실측(2026-07-22):

| type | 최종 수집 |
|---|---|
| news | **2026-06-30** (3주 전) |
| COMMUNITY | **2026-06-30** (3주 전) |
| youtube | **2025-07-27** (약 1년 전) |

`youtube` 는 알려진 API 할당량 소진 이슈지만, **news/community 가 6/30 에 동시에 끊긴 것은 별개 원인**일 가능성이 높다.

> **미디어 탭을 지금 만들어도 보여줄 데이터가 없다.** 수집 재개가 이 항목의 선행 조건이며, 백엔드 조사 결과에 따라 v1.1.0 안에서도 가장 뒤로 밀릴 수 있다.

또한 클러스터링 파이프라인(`toronchul_data_v1`, Python)은 **이미 구현돼 있으나 하루치 시범 실행 후 멈춘 상태**다(2026-03-03 하루치 21건, `media` 19,729건 중 59건만 연결). 이슈명도 `클러스터_001` 형식이라 사용자 노출 전 네이밍이 필요하다. → 자동 클러스터링을 이 배포에 넣을지는 백엔드 결정 사항.

| `src/lib/api/media.ts` | 이슈 미디어 — `home.ts` 에서 분리 |

## 4. 접속자 수 (presence)

### 4.1 노출 위치

| 위치 | 표시 | 범위 |
|---|---|---|
| 홈 / 이슈 상세 헤더 | `🌐 전체 접속 1,204명` | 웹 + 모바일 앱 합산 |
| 이슈 상세 CTA / 토론방 공지 | `👥 38명 접속 중` | 해당 방 |

> 토론방 쪽 노출 자리는 v0.7.1 §5.3 에서 만든 **채팅 공지 UI** 안이다. 공지는 "나중에 필요한 내용이 생기면 채우는" 자리로 설계됐고, presence 가 그 첫 후보다.

### 4.2 집계 단위 — **유저 단위** (초판에서 변경)

초판은 **세션 단위**(웹+앱 동시 접속 시 2로 셈)를 제안했으나, **유저 단위(userId distinct)로 정정한다.**

- "총 접속 **사용자**"라는 표시 문구와 의미가 일치한다
- 세션 단위의 유일한 장점이던 "비로그인 방문자 카운트"는 **익명 연결의 sessionId fallback** 으로 해결된다
- 백엔드 v1.3.8 설계와도 일치

### 4.3 전달 방식

폴링 대신 기존 STOMP 연결에 presence 를 얹는다.

- 방별: `/topic/room{N}/presence` — 5~10초 debounce 브로드캐스트
- 전역: 전역 토픽 또는 `GET /api/v1/presence` 폴링
- 폴백: 소켓 미연결 시 `GET /api/v1/presence` 1회 조회 후 30s 폴링
- 기존 CONNECT 인증(`Authorization: Bearer`, 대문자 — v0.7 §3 실측 확정) 규칙 그대로

> **백엔드 주의사항**: 비정상 종료로 DISCONNECT 이벤트가 유실되면 카운터가 샌다(leak). TTL / 주기적 reconcile / 하트비트 만료 설계가 필요하다. **웹은 카운트가 실제보다 높게 나올 수 있다는 전제로 UI 를 만든다** — 정확한 수치가 아니라 "활발함"의 신호로 표현한다.

### 4.4 컴포넌트

| 경로 | 역할 |
|---|---|
| `src/components/TDS/DePresenceBadge.tsx` | 접속자 수 배지 (props: `count`, `scope`) — leaf, 데이터는 props (불문율 #5) |
| `src/store/usePresenceStore.ts` | **persist 없음** — 휘발성 실시간 값이므로 `_hasHydrated` 불필요 |
| `src/lib/api/chatSocket.ts` | (수정) presence 토픽 구독 추가 |
| `src/lib/api/presence.ts` | 폴백 조회 |

```

 ├ globalCount: number
 ├ roomCounts: Record<number, number>
 └ STOMP 구독/해제 관리
```

## 5. 채팅방 이슈 컨텍스트 (백엔드 v1.3.6)

토론방을 "메시지만 흐르는 화면"에서 벗어나게 한다.

```
┌ ← 윤석열 계엄                      ← v0.7.1 구현 완료
├ 주제 탭 ────────────────────────── ← v0.7.1 구현 완료
├ ┌ 공지 ────────────────────────┐   ← v0.7.1 구현 완료 (§5.3)
│ │ 계엄은 위헌인가  62:38  [찬][반] │
│ │ 👥 38명 접속 중                │   ← §4
│ └──────────────────────────────┘
├ ─────────────────────────────────
│  (메시지 목록)
└ [입력창]
```

- 백엔드가 `GET /api/v1/room` 응답에 `issue` / `media` / `presence` 를 **추가**한다(필드 추가는 안전, 호환성 약속 v0.7.1 §2.3).
- 이 항목의 실질은 백엔드가 현재 반환하는 **전역 속보 10건**(`findTop10BreakingNews()`)을 **해당 이슈의 클러스터 미디어로 교체**하는 것이다. → §3 에 의존한다.
- v0.7.1 이 이슈 헤더(이슈로 돌아가기 링크)와 공지 영역을 이미 만들었으므로, 이 항목은 **그 공지 안에 넣을 내용**을 채우는 작업이다.
