## 0. 한 줄 정의

**이슈 페이지가 "토론 주제 목록" 에서 "이 이슈에 무슨 일이 있었고, 토론철은 그것을 어떻게 정리했나" 로 바뀐다.**

```
이슈: 도널드 트럼프 2기 행정부                    /issue/8
├ 토론위키 (v1.0.0)          — 배경·쟁점·찬반 논거, 이슈당 1장
├ ★ 사건 타임라인            — 시간 역순. 사건마다 관련 아티클
│   ├ 2026-04-02  상호관세 발표        [아티클 2]
│   └ 2026-01-20  2기 취임             [아티클 1]
├ ★ 토론철 아티클            — 이 이슈에 묶인 발행 기사 (최신순)
└ 토론 주제                  — 기존
```

---

## 1. 왜 이 순서인가

| 질문 | 답할 수 있는 콘텐츠 | 버전 |
|---|---|---|
| "이 이슈가 뭔가?" | 토론위키 | v1.0.0 |
| **"요즘 이 이슈에 무슨 일이 있었나?"** | **사건 타임라인 + 아티클** | **v1.1.0** |
| "사람들은 어떻게 생각하나?" | 토론 주제 찬반 · (채팅) | v0.7 ~ |

위키는 정적인 백과사전이고 갱신이 드물다. **사건과 아티클은 최신성을 준다.** v0.9.0 §2 의 "사건 = 실시간성 + 맥락" 이 이 버전에서 실제로 들어온다. 아티클은 동시에 토론철의 1차 데이터(찬반 수치·참여 커뮤니티 분포)를 인용하는 **자체 발행 글**이라 GEO 상 Cite Sources·Statistics 가 자연스럽게 붙는다(v0.9.0 §5.4).

## 2. 토론철 아티클

### 2.1 URL · 렌더

- **`/article/{b36}`** — 기사 PK(`toronchul_article.id`, BIGINT AUTO_INCREMENT — 데이터 v0.11.0 §6)의 소문자 base36. v0.9.0 스킴 그대로, 슬러그 없음
- 서버 렌더. 판정 규칙은 v0.9.0 §4.3d (대문자 308 · 별칭 404 · 없는 id 404). **발행 상태(`PUBLISHED`)가 아니면 404**
- `src/lib/routes.ts` 에 `articleHref(articleId)` 추가

### 2.2 화면

```
← 도널드 트럼프 2기 행정부 (이슈)
[토론철 AI 작성 · 운영진 검수]                      ← 상단 라벨 (필수)
미국 상호관세 발표, 토론철 이용자 72% "중단해야"       H1 제목
2026-04-03 발행 · 2026-04-03 수정

(요약 2~3문장)
(본문)

토론철 데이터                                       ← 1차 데이터 블록
  관련 토론 주제 · 찬반 수치 · 참여 커뮤니티 → /debate/{b36}

출처                                                ← 원문 기사 링크 목록
관련 사건 → (이슈 페이지 타임라인의 해당 사건)
```

### 2.3 발행 게이트 — 웹 노출 전 필수

v0.9.0 §5.4 와 `seo-geo` 스킬 `references/ai-news.md` 의 게이트를 이 버전의 **착수 조건**으로 삼는다. scaled content abuse 판정은 **도메인 전체**에 걸려 이슈·토론 페이지까지 같이 떨어진다.

| 게이트 | 상태 |
|---|---|
| 발행 전 **사람 검수** | ✅ 데이터 v0.11.0 §1 이 설계에 넣었다 — 자동 발행 없음, `APPROVED → PUBLISHED` 는 사람 또는 예약 |
| **AI 생성 명시** — 화면 상단 라벨 + `NewsArticle.creditText` | 웹 몫 (§2.2) |
| **가상의 기자 이름 금지** — `author`·`publisher` 는 조직(토론철) | 웹 몫 |
| **발행량을 검수 역량에 연동** | 데이터 v0.11.0 은 "하루 수십 건" 규모. 그 이상으로 늘릴 때 재검토 |
| **토론철 1차 데이터 근거** — 외부 기사 리라이트 금지 | 데이터 v0.11.0 §4(저작권: 원문 복제 검사) + 웹의 "토론철 데이터" 블록 |
| **인터넷신문 등록 여부** | ⏳ 미확인. 등록 전에는 아래 robots 정책 |

**하나라도 미충족이면 `/article/` 을 robots.txt Disallow 로 두고 시작한다.** 색인은 나중에 켤 수 있지만 판정은 회복에 수개월이 걸린다.

### 2.4 구조화 데이터 · sitemap

- `NewsArticle` + `BreadcrumbList`(홈 › 이슈 › 기사) + `about` → 이슈. `datePublished` = 발행 시각(`date_published`), `dateModified` = 마지막 리비전. `creditText` 에 AI 생성·검수 문구
- `isBasedOn` / `citation` 으로 출처 기사
- sitemap: 발행 기사만. 기사가 하루 수십 건이면 1년에 약 1만 URL — 단일 파일 한도(5만) 안이다. 넘어갈 때 `generateSitemaps` 로 샤딩(시그니처는 v0.9.0 §6.2 에 고정)

## 3. 사건 타임라인 (이슈 페이지)

v1.x.0 문서 §2 에서 옮겨 왔다. 사건은 이슈 안에서 일어난 사실 단위이고 **읽기 전용**이다(온톨로지가 제안하고 사람이 승인 — 데이터 v0.10.0).

- 이슈 상세에 **사건 섹션**: 발생 시각 내림차순 타임라인. 사건 카드 = 제목 · 발생 시각 · 요약 · 관련 아티클 수
- 사건이 소유하는 것은 **미디어·아티클 묶음뿐** — 채팅방이나 위키를 갖지 않는다(v1.x.0 원문 결정 유지)
- **서버 렌더.** 사건 목록은 크롤러가 읽는 "최신성" 본문이다
- **사건 상세 페이지 `/event/{b36}` 은 이 버전에서 열지 않는다.** v0.9.0 이 URL 자리만 예약했다. 사건 하나에 제목·시각·요약 몇 줄뿐이면 얇은 페이지가 사건 수만큼 생긴다. 사건마다 아티클이 쌓여 **페이지당 고유 본문이 생긴 뒤** 연다. 그때까지 사건은 이슈 페이지 안의 앵커(`/issue/{b36}#event-{b36}`)로만 가리킨다
- 커서 페이징 전제로 받는다 — 사건 생성이 자동화(온톨로지)되면 이슈당 건수가 크게 늘 수 있다

## 4. 백엔드에 요청할 것

**불문율 #1** — 아래는 **요청 목록**이지 타입이 아니다. 웹은 배포된 Swagger·실 curl 로 확인한 필드만 쓴다. 지금 Swagger 에 있는 사건 API 는 관리자용 `POST·DELETE /api/v1/admin/issue/{issueId}/events`(사건 연결·해제)뿐이고, **사건·아티클 공개 조회 API 는 없다**(2026-10-19).

| # | 요청 | 비고 |
|---|---|---|
| A-1 | **아티클 단건 공개 조회** — 익명 200, 미발행·없는 id 는 404 | 웹 SSR 은 토큰 없이 부른다 |
| A-2 | **이슈별 아티클 목록** — 최신순, 커서 페이징 | 이슈 페이지 섹션 |
| A-3 | **이슈별 사건 타임라인 공개 조회** — 발생 시각 내림차순, 커서 페이징, 사건별 관련 아티클 id | `feature/event-timeline-versions` 의 공개 읽기 경로 |
| A-4 | **발행 아티클 전체 목록(sitemap 용)** — id·수정 시각만, 페이징 | sitemap lastmod |
| A-5 | 아티클 응답에 데이터 v0.11.0 §2 의 **기사 요소**(제목·요약·본문·발행/수정 시각·이슈·사건·출처) + **AI 생성 여부** | 화면·JSON-LD 가 이 필드를 그대로 쓴다 |

> 고객사(티머니) API 와는 별개다. 그쪽은 인증·미터링·민감도 필터가 붙는 B2B 경로이고(데이터 v0.11.0 §5), 웹은 **공개 읽기** 경로가 필요하다. 같은 테이블을 읽되 엔드포인트를 섞지 않는 편이 안전하다 — 미터링 경로에 크롤러 트래픽이 섞이면 과금 집계가 오염된다.
