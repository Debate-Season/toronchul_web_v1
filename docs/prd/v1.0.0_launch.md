# 정식 출시 v1.0.0 — 토론위키로 비로그인 페이지에 본문을 만든다

> **작성일**: 2026-10-19
> **성격**: **정식 출시 버전.** v0.9.0(SEO/GEO 기반)이 깔아 둔 URL·SSR·구조화 데이터 위에, 검색과 비로그인 방문자가 읽을 **본문**을 채운다.
> **선행 문서**: `docs/prd/v0.9.0_seo-geo.md` (URL 스킴 `/issue/{b36}` `/debate/{b36}`, SSR 초기 데이터 패턴, JSON-LD)
> **후속 문서**: `docs/prd/v1.1.0_toronchul-article.md` (토론철 아티클 · 사건 타임라인) · `docs/prd/v1.x.0_issue-context.md` (미디어 · 접속자 수 · 채팅방 컨텍스트)
>
> 토론위키는 원래 `v1.1.0_issue-context.md` §1 에 있었다. "게시본이 0건이라 출시 이후로 미룬다" 가 이유였는데, 아래 §1 의 실측으로 **위키가 없으면 출시 페이지가 검색에서 의미가 없다** 는 게 드러나 출시 범위로 당겼다(2026-10-19 결정).

## 1. 문제 — 비로그인 토론방에는 읽을 것이 없다

v0.9.0 으로 크롤러가 받는 HTML 에 제목·찬반 수치·토론 주제 목록이 들어갔다. 그래도 **본문이 거의 없다.** 2026-10-19 로컬 프로덕션 빌드를 Googlebot UA 로 측정했다.

| 페이지 | 크롤러가 읽는 텍스트 | 내용 |
|---|---|---|
| v0.9.0 이전 (모든 페이지) | **30자** | 전역 네비게이션뿐 |
| `/issue/8` | **158자** | 이슈 제목 + 토론 주제 2개 제목 + 찬반 % |
| `/debate/1p` | **145자** | 토론 주제 제목 + 찬반 % + "로그인 후 대화에 참여할 수 있어요" |

v0.9.0 합격선(500자, 위키 게시 시 2,000자)에 못 미친다. 원인은 둘이다.

1. **채팅 내역은 비로그인에게 보이지 않는다.** `GET /api/v1/chat/rooms/{roomId}/messages` 가 401 이다(v0.9.0 §7-1). 열더라도 닉네임·소속 커뮤니티가 붙은 사용자 발언을 검색엔진에 공개하려면 약관·개인정보처리방침 근거가 필요하다(§7-2).
2. **이슈를 설명하는 글이 없다.** 이슈는 제목과 토론 주제 목록뿐이다. "이 이슈가 무엇인가" 를 말하는 문단이 한 줄도 없다.

**토론위키가 두 문제를 한 번에 푼다.** 토론철 AI 가 이슈의 배경·쟁점·찬반 논거를 쓰고 운영진이 검수해 게시하는 문서다(백엔드 v1.4.0). 사용자 발언이 아니라 **토론철이 발행하는 글**이라 개인정보 문제가 없고, 이슈 페이지와 토론방 양쪽에 같은 출처의 본문을 줄 수 있다.

## 3. 데이터 — `GET /api/v2/wiki?issue-id=N`

2026-10-19 실측(issue 8): 익명 200, 게시본이 없으면 전 필드 null(에러 아님). 없는 이슈는 404 `NOT_FOUND_ISSUE`(백엔드 v1.4.0 문서).

```json
{"issueId":8,"issueTitle":"도널드 트럼프 2기 행정부","status":null,"content":null,"model":null,"revisionId":null,"updatedAt":null}
```

| 필드 | 웹 용도 |
|---|---|
| `content` (Markdown) | 이슈 상세 본문 |
| `status` | 게시 여부. 게시본만 렌더 |
| `updatedAt` | `Article.dateModified`, sitemap lastmod — **처음으로 "실제 수정 시각" 이 생긴다** (v0.9.0 §6.2 는 생성일로 대신하고 있다) |
| `model` | AI 생성 고지 문구 근거 (§4.3) |

> **불문율 #1** — 게시본이 0건이라 `content` 가 실제로 어떤 Markdown 요소를 쓰는지 아직 확인하지 못했다. 타입은 위 실측 필드만으로 만들고, 첫 게시본이 나오면 렌더 범위(표·각주 여부)를 실측으로 확정한다.

### 3.1 백엔드에 요청할 것

| # | 요청 | 이유 |
|---|---|---|
| **B-1** | 위키 응답에 **`summary` (2~3문장 요약)** 필드 | 사이드바 카드(§4.2)와 메타 설명에 쓴다. 지금 응답에 요약이 없다. 리비전의 `edit_summary` 는 "변경 사유" 라 용도가 다르다. 생성 시 LLM 이 본문과 함께 쓰게 하는 게 가장 싸다 (데이터 리포 v0.11.0 아티클도 같은 방식으로 `summary` 를 둔다) |
| **B-2** | **위키 생성·게시 파이프라인 가동** — 백엔드 v1.4.0 Phase 2 의 유일한 블로커가 `ANTHROPIC_API_KEY` 미확보였다 | 게시본 0건이면 이 버전 전체가 빈 화면이다 |

B-1 이 오기 전에는 **본문 첫 문단**(정의 문단)을 요약으로 쓴다. B-1 이 오면 교체한다. 첫 문단 폴백은 문장 중간에서 끊지 않도록 문장 단위로 자른다.

## 4. 화면

### 4.1 이슈 상세 — 위키 본문

```
← 홈으로
도널드 트럼프 2기 행정부                       H1
토론 주제 2개

┌ 토론위키 ───────────────────────────────┐
│ (Markdown 본문 — H2/H3 목차 유지)          │   ← 서버 렌더
│ 토론철 AI 가 작성하고 운영진이 검수했습니다. │
│ 최종 수정 2026-10-20                       │
└──────────────────────────────────────────┘

토론 주제                                       (기존)
참여 커뮤니티                                   (기존)
```

- **서버 렌더.** v0.9.0 의 `initialData` 패턴을 그대로 쓴다 — 서버 페이지가 토큰 없이 위키를 받아 클라이언트 뷰에 넘기고, 첫 렌더부터 HTML 에 본문이 있다
- **H2/H3 를 살린다.** 부분 인용·목차가 GEO 의 인용 가능성을 만든다(v0.9.0 §5.1). 문서 H1 은 이슈 제목 하나뿐이므로 위키의 `#` 은 H2 로 한 단계 내린다
- **미게시면 섹션을 그리지 않는다.** "준비 중" 안내도 두지 않는다 — 모든 이슈에 같은 빈 문구가 반복되면 크롤러에게는 얇은 중복 콘텐츠다. **`noindex` 도 걸지 않는다**(v0.9.0 §5.1: 임계값 noindex 는 flapping 을 만든다)
- **Markdown 은 원시 HTML 을 렌더하지 않는다.** 링크는 외부로 나가면 `rel="noopener nofollow"`. 스타일은 디자인 토큰만(불문율 #6)

### 4.2 토론방 — 우측 사이드바 하단 위키 요약 카드

```
본문                                   우측 사이드바
┌ ← 도널드 트럼프 2기 행정부  ┐      ┌ 미국은 관세전쟁을 중단해야 하는가? ┐
├ 주제 탭 ─────────────── │      │ 72% ▓▓▓▓▓▓▓░░░ 28%               │
│                          │      │ [👍 찬성] [👎 반대]                │  ← ThreadPanel (기존)
│  (대화)                   │      └──────────────────────────────────┘
│                          │      ┌ 토론위키 ─────────────────────────┐
│                          │      │ 도널드 트럼프 2기 행정부            │
│                          │      │ (요약 2~3문장)                     │  ← ★ 신규
│                          │      │ 토론철 AI 작성 · 운영진 검수         │
│                          │      │ 위키 전체 보기 →  (/issue/8)        │
└ [입력창]                 ┘      └──────────────────────────────────┘
```

- **자리**: 토론방이 우측 사이드바에 내주는 슬롯(`RNB_SLOT_ID`)의 `ThreadPanel` **아래**. 같은 포털 안에 둔다
- **`md` 미만(사이드바 없음)**: `ThreadPanel` 과 같은 규칙 — 본문 상단 주제 패널 아래에 같은 카드를 놓고 CSS 로 한쪽만 보인다
- **⚠ SEO 상 중요한 구현 조건** — 포털은 마운트 후에만 그려지므로 **데스크톱 사이드바 카드는 서버 HTML 에 없다.** 크롤러가 읽는 건 `md` 미만용 본문 흐름 안의 카드다(Googlebot 은 모바일 우선 색인). 따라서 **모바일용 카드를 서버 렌더 경로에서 빼면 안 된다.** 기존 `ThreadPanel` 이 같은 구조라 그대로 따른다
- **카드는 요약만** 보여 준다. 본문 전체를 토론방에도 그리면 같은 위키 본문이 이슈 페이지와 모든 토론 페이지에 반복되어 중복 콘텐츠가 된다. 전문은 이슈 페이지 한 곳에만
- **미게시면 카드를 그리지 않는다**
- 컴포넌트: 표현은 TDS 카드(`DeWikiSummaryCard`, props 로만 데이터 주입 — 불문율 #5), 데이터 주입은 `DebateRoom`

### 4.3 AI 생성 고지

위키는 토론철 AI 가 쓰고 운영진이 검수한다(백엔드 v1.4.0: DRAFT → ADMIN 승인 → PUBLISHED). 화면과 구조화 데이터에 그 사실을 그대로 적는다.

- 화면: "토론철 AI 가 작성하고 운영진이 검수했습니다" + 최종 수정일
- JSON-LD: `Article.creditText` 에 같은 문구. **`author` 에 가상의 사람 이름을 만들지 않는다** — 조직(토론철)
- 근거: Google 스팸 정책의 scaled content abuse 는 생성 방식이 아니라 페이지당 가치를 본다. 검수 게이트와 고지가 그 가치를 증명하는 장치다(v0.9.0 §5.4, `seo-geo` 스킬 `references/ai-news.md`)

## 8. 구현 현황 (2026-10-19, 브랜치 `feat/v1.0.0-wiki`)

**웹 쪽은 끝났고, 게시본이 생기는 순간 그려진다.** 지금은 게시본 0건이라 운영 화면은 그대로다(빈 안내도 없음, §4.1).

| 파일 | 내용 |
|---|---|
| `src/lib/api/wiki.ts` | `GET /api/v2/wiki` — 실 curl·Swagger `WikiResponse` 필드만. `isPublishedWiki` 는 `status === "PUBLISHED"` + 본문·리비전·갱신 시각이 모두 있을 때만 |
| `src/components/wiki/IssueWiki.tsx` | **서버 컴포넌트.** `react-markdown@10.1.0` + `remark-gfm@4.0.1`(브라우저 번들 0건 — 빌드 산출물 확인), `skipHtml`(원시 HTML 제거), 제목 두 단계씩 내림(`#`→H3·`##`→H4, 문서 H1 은 이슈 제목·H2 는 섹션), 외부 링크 `noopener nofollow`, 이미지 렌더 안 함, `id="wiki"` 앵커, 고지 + 최종 수정일 |
